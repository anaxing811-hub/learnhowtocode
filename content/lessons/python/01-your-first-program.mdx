Here is a complete Python program. Press **Run** — this is real CPython, compiled to WebAssembly and running in this tab.

```python run title="hello.py"
print("Hello, world!")
```

One line. Compare that to the C++ version, which needed an `#include`, a `main` function, a namespace prefix and a `return`. Python does not need any of it:

- There is no `main`. A Python file *is* the program; the interpreter runs it top to bottom.
- There is no compile step you have to invoke. Python reads your source and executes it.
- There is no `#include` for basic output. `print` is always available.

That difference is the whole trade Python makes: less to type, less to think about, and in return your program runs considerably slower and mistakes surface later. For a beginner, and for data work, that trade is usually worth it.

## print does more than one thing

```python run title="print.py"
print("one", "two", "three")
print("no newline after this", end=" -> ")
print("see?")
print()
print("Sum:", 2 + 3)
```

Given several arguments, `print` joins them with a space. `end=` changes what it puts at the end — a newline by default. A bare `print()` emits just the blank line.

<Callout type="note" title="Quotes">
`'single'` and `"double"` quotes mean exactly the same thing in Python. Pick one and be consistent; use the other when your text contains the first, as in `"it's fine"`.
</Callout>

## Comments

```python run title="comments.py"
# Everything after a hash is ignored.
print("this runs")  # including at the end of a line
```

Python has no `/* ... */` block comment. Multiple `#` lines are the idiom.

<KeyPoints>
- A Python file is a program; there is no `main` and no separate compile step.
- `print` takes many values, joins them with `sep` (default a space) and ends with `end` (default a newline).
- `#` starts a comment and runs to the end of the line.
</KeyPoints>
