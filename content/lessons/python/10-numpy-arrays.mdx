A Python list can hold anything, which is exactly why it is slow: every element is a separate object with its own type tag, scattered across memory. A NumPy array holds one type, laid out in a single contiguous block, so the CPU can march through it.

```python run title="first-array.py"
import numpy as np

a = np.array([1, 2, 3, 4, 5])

print(a)
print("shape:", a.shape)
print("dtype:", a.dtype)
print("bytes per element:", a.itemsize)
```

## Vectorised operations

The rule for writing good NumPy: **do not write loops over elements.** Express the operation on the whole array.

```python run title="vectorised.py"
import numpy as np

a = np.array([1, 2, 3, 4, 5])

print(a * 2)
print(a + a)
print(a ** 2)
print(np.sqrt(a))
print(a > 3)             # a boolean array
print(a[a > 3])          # boolean indexing — select where True
```

Every one of those runs a tight C loop under the hood. The equivalent Python `for` loop does the same arithmetic tens of times slower.

```python run title="speed.py"
import numpy as np
import time

n = 1_000_000
values = list(range(n))
array = np.arange(n)

start = time.perf_counter()
total_py = sum(v * v for v in values)
py_time = time.perf_counter() - start

start = time.perf_counter()
total_np = int((array * array).sum())
np_time = time.perf_counter() - start

print("same answer:", total_py == total_np)
print(f"python: {py_time * 1000:.1f} ms")
print(f"numpy:  {np_time * 1000:.1f} ms")
print(f"speedup: {py_time / np_time:.1f}x")
```

## Creating arrays

```python run title="creating.py"
import numpy as np

print(np.zeros(5))
print(np.ones((2, 3)))
print(np.arange(0, 10, 2))
print(np.linspace(0, 1, 5))        # 5 evenly spaced points, endpoints included
print(np.full((2, 2), 7))

rng = np.random.default_rng(seed=42)
print(rng.normal(size=5).round(3))
```

<Callout type="tip" title="Seed your random numbers">
`np.random.default_rng(seed=42)` gives you a generator that produces the same sequence every run. When a result is surprising, being able to reproduce it exactly is the difference between debugging and guessing.
</Callout>

## Shape, not length

```python run title="shapes.py"
import numpy as np

m = np.arange(12).reshape(3, 4)
print(m)
print("shape:", m.shape)
print("row 1:", m[1])
print("column 2:", m[:, 2])
print("a 2x2 block:", m[0:2, 1:3], sep="\n")
print("transposed:", m.T, sep="\n")

print("sum of all:", m.sum())
print("sum down each column:", m.sum(axis=0))
print("sum across each row:", m.sum(axis=1))
```

`axis=0` means "collapse the rows", giving one number per column. `axis=1` collapses the columns. Getting these the right way round is most of the difficulty of learning NumPy, and the way to remember it is: *the axis you name is the one that disappears*.

## Views, not copies

```python run title="views.py"
import numpy as np

a = np.arange(6)
b = a[2:5]        # a view into a's memory, not a copy
b[0] = 999

print("a:", a)
print("b:", b)
print("b owns its data?", b.base is None)

c = a[2:5].copy()
c[0] = -1
print("a is untouched:", a)
```

Slicing a NumPy array gives you a **view**. This is what makes slicing free even on enormous arrays, and it is also a source of surprise if you assumed you had a copy. Ask for `.copy()` when you need independence.

<KeyPoints>
- An array is one dtype in one contiguous block — that is the whole source of the speed.
- Express operations on whole arrays; a per-element Python loop throws the advantage away.
- `axis=0` collapses rows, `axis=1` collapses columns: the named axis disappears.
- Slicing returns a view that shares memory. Use `.copy()` when you need a separate array.
</KeyPoints>
