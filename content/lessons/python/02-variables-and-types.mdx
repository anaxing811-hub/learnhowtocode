In C++ you announce a variable's type and it never changes. Python does the opposite: a variable is just a name pointing at a value, and you can point it somewhere else entirely.

```python run title="types.py"
count = 5              # int
price = 1.25           # float
name = "Ada"           # str
ready = True           # bool
nothing = None         # NoneType — the absence of a value

print(count, price, name, ready, nothing)
print(type(count), type(price), type(name))
```

```python run title="rebinding.py"
x = 5
print(x, type(x))

x = "now I am text"
print(x, type(x))
```

That is legal, and it is also how a large Python program turns into a mystery. The values still have types; only the *names* are flexible.

## Numbers

```python run title="numbers.py"
print(7 / 2)      # 3.5   — true division, always a float
print(7 // 2)     # 3     — floor division
print(-7 // 2)    # -4    — floors toward negative infinity
print(7 % 2)      # 1     — remainder
print(2 ** 10)    # 1024  — exponent
```

Two things to file away. First, `/` in Python always gives a float, unlike C++ where `7 / 2` is 3. Second, `//` *floors* rather than truncating, so `-7 // 2` is `-4`, not `-3`. C++ integer division truncates toward zero. If you port code between the languages, this bites.

<Callout type="tip" title="Python integers do not overflow">
`2 ** 200` is an exact answer, not garbage. Python integers grow to whatever size they need, which is why it is a comfortable language for number-theory puzzles and a slow one for tight loops.
</Callout>

```python run title="bignum.py"
print(2 ** 200)
```

## Converting on purpose

```python run title="convert.py"
text = "42"
number = int(text)
print(number + 1)

print(float("3.5") * 2)
print(str(99) + " bottles")
```

Python will not add a string to a number for you. `"42" + 1` is an error, and that error is a feature — it catches a genuine confusion rather than silently guessing.

```python run title="type-error.py"
print("42" + 1)
```

Read that traceback. The last line names the error type and the problem; the lines above show where it happened. Tracebacks read bottom-up.

## f-strings

The modern way to build text out of values:

```python run title="fstrings.py"
name = "Ada"
year = 1843
score = 0.87231

print(f"{name} published in {year}")
print(f"Accuracy: {score:.1%}")
print(f"Padded: {year:>10}")
```

The `f` prefix lets you drop expressions inside `{}`. After a colon comes a format spec: `.1%` means "as a percentage with one decimal", `>10` means "right-align in ten columns". You will use these constantly once you start printing tables of numbers.

<KeyPoints>
- Names are untyped; values are typed. `type(x)` tells you what you actually have.
- `/` is float division, `//` floors (toward negative infinity), `%` is the remainder.
- Python integers are arbitrary precision and never overflow.
- f-strings (`f"{value:.2f}"`) are the standard way to format output.
</KeyPoints>
